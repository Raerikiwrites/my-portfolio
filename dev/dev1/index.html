    From Scratch #1 – First Steps into Web3 & Solidity

    Date: September 2, 2025

    Today officially marks the start of my From Scratch journey into blockchain development. My goal is to learn daily, document everything I understand (and don’t understand), and keep track of my growth in both technical knowledge and personal reflections.

    For Day 1, I decided to dive in with two popular beginner-friendly resources:
    - LearnWeb3: a structured curriculum that introduces blockchain and Web3 concepts step by step.
    - CryptoZombies: an interactive game-like tutorial that teaches Solidity through building a zombie-themed dApp.

    I also set up a brand-new crypto wallet, experimented with faucets (more on that later), and even tried deploying my first smart contract.

    Starting Out with LearnWeb3

    I kicked things off today with LearnWeb3, which is designed to guide beginners into blockchain development step by step. At first, it felt like a friendly introduction, covering the basics of programming, what a blockchain is, and what Web3 really means.

    The pace was steady, but as I got deeper—especially when it came to Solidity and building my first dApp—things started to feel a little overwhelming. Still, I tried to take notes carefully, almost like I was building my own schoolbook on Web3.

    What is Programming?

    Programming is basically telling a computer what to do using a language it understands. Just like humans use English, Yoruba, or French to communicate, computers have their own “languages” like Python, JavaScript, or Solidity.

    What is a Blockchain?

    A blockchain is a distributed and decentralized ledger that records transactions in a series of blocks linked together using cryptographic hashes.

    In simpler terms, a blockchain is a digital ledger (like a notebook) that’s shared across many computers. Instead of one person keeping the records, everyone holds a copy, so it’s almost impossible to secretly alter it.

    What is Web3?

    Web3 is the version of the internet where applications run on blockchains and are community-owned rather than controlled by a single centralized entity.

    Put simply, it’s like moving from a classroom where one teacher controls the lesson (Web2) to a group project where everyone participates and has a say. This structure allows for shared ownership, transparency, and collaboration.

    What is Ethereum?

    Ethereum is a decentralized, open-source blockchain platform that supports smart contracts and enables the creation of decentralized applications (dApps).

    In simpler terms, Ethereum is like a global computer that anyone can use. Instead of relying on a single company’s servers, people all over the world contribute their computers to run programs and applications, making it more open, secure, and resistant to control by one authority.

    Setting Up a Crypto Wallet

    To interact with Ethereum and Web3 applications, the first step was setting up a crypto wallet.

    I used MetaMask, one of the most popular non-custodial wallets. MetaMask works as a browser extension and mobile app, allowing you to securely store your private keys and manage ETH and tokens. After setup, the wallet can connect directly to decentralized applications (dApps) with just a few clicks, making it a gateway to the Ethereum ecosystem.

    Introduction to Solidity & My First dApp

    Solidity is the programming language used to build smart contracts on Ethereum, the foundation of decentralized applications (dApps). Unlike traditional applications, dApps run on the blockchain, meaning once deployed, they are immutable. This makes testing and careful deployment especially important.

    While building my first dApp, I experienced both excitement and challenges:

    • 🎉 My joy was unmatched when I finally discovered a faucet that allowed me to use a completely new wallet to receive testnet tokens (shoutout to Google Cloud Web3).
    • 😅 Deployment proved to be a headache, but it finally worked—it turned out to be a network issue.

    For now, I’ve decided to pause my LearnWeb3 lessons until I gain a stronger grasp of Solidity itself. Taking things step by step feels like the right approach to build a solid foundation.

    CryptoZombies

    After wrestling with LearnWeb3 and realizing I need a deeper grip on Solidity, I decided to switch things up and dive into CryptoZombies.

    The introduction immediately felt different: less formal, more playful. Instead of throwing me into dense documentation, it frames Solidity through building a zombie game.

    To make things more convenient and relatable, I adjusted the original CryptoZombies example. Instead of a Zombie Factory, I built a simple Pet Factory contract that creates pets with unique DNA. The structure and concepts are the same, but the new theme makes it easier to understand without the “zombie” flavor.

    Now let’s break it down step by step…

    Version Declaration

    pragma solidity >=0.5.0 <0.6.0;
    • This line tells the compiler which version of Solidity can compile this code.
    • It means: “This contract works with Solidity versions starting from 0.5.0 up to (but not including) 0.6.0.”

    Contract Definition

    contract PetFactory {

}

    • A contract in Solidity is like a class in other languages.It contains state variables, functions, and events.

    • Here, we name the contract PetFactory.

    Event

    event NewPet(uint petId, string name, uint dna);

    • Events are like logs that get recorded on the blockchain.They let external apps (like web apps) know when something happens.

    • We create a new pet, we fire an event with its ID, name, and DNA

    State Variables

    uint dnaDigits = 16;
uint dnaModulus = 10 ** dnaDigits;

    • dnaDigits: We decide the length of the pet’s DNA → 16 digits.

    • dnaModulus: Makes sure our DNA doesn’t exceed 16 digits. (e.g., if a number is too big, % dnaModulus keeps it within range).

    Struct

    uint dnaDigits = 16;
struct Pet {
    string name;
    uint dna;
}
    • Structs let us create custom data types.
    • Here a Pet has:
      • a name (string)
      • a dna (unique number that represents its traits).

    Array of Pets

    Pet[] public pets;

    • This creates a dynamic array to store all pets

    • It’s marked public, so Solidity automatically gives us a getter function (i.e Anyone can check what pets exist.)

    Internal Create Function

    function _createPet(string memory _name, uint _dna) private {
    uint id = pets.push(Pet(_name, _dna)) - 1;
    emit NewPet(id, _name, _dna);
}
    • _createPet: A private function (only usable inside the contract)
    • What it does:
      • Push a new Pet into the pets array
      • id = index of the new pet
      • Emit an event to let the outside world know the pet was created

    Random DNA Generator

    function _generateRandomDna(string memory _str) private view returns (uint) {
    uint rand = uint(keccak256(abi.encodePacked(_str)));
    return rand % dnaModulus;
}
    • _generateRandomDna: Generates a pseudo-random number from a string input.
    • Uses keccak256 (a hashing function in Ethereum).
    • dnaModulus ensures DNA is always 16 digits.
    • Marked view because it doesn’t change the blockchain, just reads from it.

    Public Function to Create Pets

    function createRandomPet(string memory _name) public {
    uint randDna = _generateRandomDna(_name);
    _createPet(_name, randDna);
}
    • This is the main entry point for users
    • Anyone can call createRandomPet("Fluffy"), and it will:
      1. Generate a DNA from the name
      2. Create the new pet
      3. Save it to the blockchain and emit an event.

    Closing Thoughts on Day 1

    Day 1 is done, and honestly, I feel proud. Solidity has always felt like a mountain, but breaking it down into pieces made it much less intimidating. It’s the first time I didn’t just copy-paste code but actually understood why it works.

    For anyone who wants to take the same path, here are a few resources I found useful:

    • CryptoZombies – learn by building your own zombie game
    • Solidity Docs – best for clarifying syntax
    • FreeCodeCamp Solidity Tutorial – step-by-step video guide

    Feeling excited for what’s ahead. One day down, many more to go! 🚀
